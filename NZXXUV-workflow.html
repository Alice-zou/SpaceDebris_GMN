Operating it

Start in two steps

Order matters — the camera stream must exist before capture tries to read it.

STEP 1

Camera → RTSP

Tunes the network, opens the FLIR camera with PySpin, and publishes to MediaMTX.

~/Desktop/Workspace/RTSP/start_spinnaker_rtsp.sh
STEP 2

Wheel + capture (wrapper)

Run the wrapper — not StartCapture.sh, which starts capture only:

~/Desktop/Workspace/start_nzxxuv.sh NZXXUV
Good to know Capture starts only when it is night at the configured coordinates. At Lisbon it begins immediately after dusk; run it during the day and it will wait until sunset.
Stage 1

The RTSP stream

start_spinnaker_rtsp.sh raises eth0 MTU to 9000 and the kernel socket buffers to 16 MB, then launches spinnaker_to_rtsp.py on pyenv Python 3.10.14 (the only interpreter with PySpin). The script reads spinnaker.config, opens the camera, and publishes through MediaMTX at rtsp://127.0.0.1:8554/live.

Stage 2

Capture & the filter wheel

The start_nzxxuv.sh wrapper is the launch hub — it starts two things at once. (RMS's own StartCapture.sh only runs capture; an RMS update removed the old in-launcher wheel start, so the wrapper owns that coupling now and survives future updates.)

Records the sky

Runs RMS.StartCapture in the vRMS venv, reading the RTSP stream. Every ~256-frame block (≈10 s) it writes an FF frame plus FS field-sum and FT frame-time files into CapturedFiles/, and saves timelapse frames to FramesFiles/.

Cycles the filter

The wrapper launches filter_cycle.py (gated to NZXXUV only). Instead of a fixed duty cycle it runs a whole-night session: a Natural Light calibration burst to build the plate solution, then a long UV observing loop (with optional short NL drift checks), then a closing NL burst that brackets the night. Each change is appended to filter_history.txt; on shutdown the wheel parks back at UV.

Stars are invisible in UV, so a UV streak can't be plate-solved on its own. But for a fixed camera pixel → (az, alt) is constant in time, so a streak's sky position = its pixel coordinates + the frame's UTC + a plate solution built from the Natural Light frames. NL is calibration, not something that must coincide with a detection — see fw-python-main/FILTER_CYCLE.md.

Stage 3 · the custom logic

Detecting meteors in UV without stars

Standard RMS skips meteor detection unless an FF has ≥ 20 stars. In UV there are essentially none — so detection would never run. The customised DetectStarsAndMeteors.py looks up the filter that was active when each frame was captured and overrides that rule for UV.

filter_name = getFilterForTime(config, capture_dt)   # reads filter_history.txt
if (filter_name == 'UV') or (stars >= config.ff_min_stars):
    log.info('detecting meteors')
    print('detecting meteors', flush=True)   # shown in the terminal
    ... run meteor detection ...
Verified 2026-07-06 A real capture reprocessed 6 UV frames with only 5–6 stars each (below the 20 threshold). Each printed detecting meteors to the terminal and logged UV filter in use, detecting meteors regardless of star count… — detection ran, exactly as intended.
Root cause fixed Detection originally read the history from the per-station data_dir (~/RMS_data/NZXXUV/) while filter_cycle.py wrote to ~/RMS_data/filter_history.txt. One physical wheel ⇒ one fixed history path; both sides now agree.

Where it lands

Data storage map

~/RMS_data/
├── filter_history.txt          # machine-wide UV / Natural Light timeline
├── logs/                       # <date>_NZXXUV_filterwheel.txt
└── NZXXUV/
    ├── CapturedFiles/NZXXUV_<start>/   # raw FF/FS files (auto-pruned when full)
    ├── ArchivedFiles/NZXXUV_<start>/   # night result + .tar.bz2 bundles
    ├── FramesFiles/<year>/<doy>/       # timelapse JPEGs
    ├── TimeFiles/<year>/               # frame-time (FT) files
    └── logs/                          # log_NZXXUV_*.log, detection_log_*.log
Two homes CapturedFiles holds the heavy raw frames (~3.7 MB each) and is auto-pruned as the disk fills. ArchivedFiles is the durable "night result" — small plots, summaries and the two bundles.
